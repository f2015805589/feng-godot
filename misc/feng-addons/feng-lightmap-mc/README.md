# Feng Lightmap MC

`FengLightmapVolume` bakes static scene triangles into UV2 surface atlases with a CPU Monte Carlo integrator. `FengLightmapData` persists the raw samples, variance and input signature; `LightmapGIData` provides the runtime display. This addon is independent of Magic GI's PRT and Surfel modes.

## Responsibilities

- `feng_lightmap_volume.gd`: editor actions, asynchronous bake/cancel, sky capture, validated publication and display binding.
- `feng_lightmap_scene_inputs.gd`: one scene traversal for receiver/transport geometry, materials and analytic lights; deterministic transport-input signatures. It owns no threads, scene nodes or saved resources.
- `native/`: CPU transport integration over immutable input snapshots.
- `feng_lightmap_data.gd`: persisted results, chart certificates and cached display reconstruction.

Design references: [MagicDawn introduction](https://developer.unity.cn/projects/6780a20dedbc2a001ee971bb), [UV lightmap compression](https://magicdawn.tencent.com/academic/pages/uv.html), and [temporal lightmap sets](https://magicdawn.tencent.com/academic/pages/ndgi.html). The estimator and its supported surface model are defined below.

## Bake from the editor

1. Enable `res://addons/feng-lightmap-mc/plugin.cfg`, then add or select `FengLightmapVolume`.
2. Set its local `bounds` AABB. A green bounds gizmo appears when the volume is selected. `source_root_path` can further restrict receiver objects.
3. Set `atlas_resolution`, `samples_per_texel` and `worker_count`. Defaults are 128×128, 256 samples per covered texel and four CPU workers. Each receiver mesh has its own atlas layer; UV2 must be non-overlapping and lie in `[0,1]`.
4. Select the environment model. The default `CAPTURE_SCENE_SKY` freezes the selected `WorldEnvironment` sky as a linear HDR radiance panorama. A canonical FengSky atmosphere uses a private Environment/Sky/ShaderMaterial and isolated viewport to omit only solar disks already represented by collected analytic directional lights. Atmospheric scattering and sky-only solar disks are retained; the visible scene's resources are never edited. Other skies must be ready before capture. `BLACK_OVERRIDE` and `UNIFORM_OVERRIDE` are explicit alternative boundary conditions.
5. Click **Bake CPU Lightmap**. Scene collection and sky readback occur on the main thread; native CPU path tracing runs on a worker thread and keeps the editor responsive. The Inspector reports native progress. **Cancel Bake** cancels the estimator and keeps the previous saved lightmap; partial results are never published.
6. After success, the resource is saved at `output_resource_path` and assigned to `baked_data`. Set `enabled` to display this independent result. Avoid displaying two separate indirect-light solutions simultaneously when comparing them.

The default resource path is `res://bake/lightmap/box_white_lightmap.res`. Baking does not enable the volume automatically. The scene's geometry, materials, lights, receiver bounds and paths are checked again before saving an asynchronous bake: if they changed while tracing, the previous saved lightmap is kept and the Inspector asks for a new bake. A failed attempt identifies the retained resource in its report. **Check Saved Bake Inputs** compares a persisted transport-input hash with the current geometry, materials, emission and lights. Legacy data without this signature is unverified. This is an explicit editor action, with no new per-frame or startup scene traversal. The sky is an explicitly frozen capture-time source and still requires rebaking after sky/time-of-day changes. Closing the scene requests cancellation and joins its CPU worker before releasing input snapshots.

Bounds select complete receiver objects, not clipped fragments. A whole `MeshInstance3D` AABB must lie inside the volume and chosen receiver subtree. Objects outside that selection remain complete transport-only geometry: they still occlude, reflect and emit light, require no UV2, and receive no atlas. Unsupported inputs outside the receiver range still fail validation because they affect light transport. The report lists transport-only objects and excluded lights.

## What “unbiased” means here

For each covered UV2 texel, the backend clips triangles against the texel square, chooses a clipped region proportional to its UV area, then uniformly samples a point within that region. The target is the texel's UV-area-averaged incoming diffuse irradiance divided by pi. The runtime renderer applies the receiving material's albedo and diffuse metal fraction; the material shader adds self-emission. GGX and Burley affect intermediate surface transport, while a single diffuse lightmap cannot itself encode view-dependent specular reflections.

At intermediate vertices the declared BSDF is Lambert or Burley diffuse plus isotropic Smith GGX/Schlick specular, using constant linear material parameters and interpolated vertex normals. The native BSDF clips directions to the geometric front hemisphere. It follows the Godot material F0 convention but does not claim to reproduce every FRP split-sum/DFG compensation or renderer-specific approximation. Source geometry is converted from Godot's clockwise winding to the integrator's cross-product convention, including mirrored transforms. Normals use the inverse-transpose world transform.

Emissive triangles are selected proportional to area times luminance. Panorama cells are selected with their actual angular measure and radiance weighting; constant environments use the corresponding uniform-source sampler. Next-event estimation and BSDF continuation use matching MIS densities. Russian roulette starts after the initial vertices; its survival probability is included in the continuation throughput and competing MIS density. There is no fixed maximum bounce count, radiance clamp, denoiser, image filter or lossy compression in the saved raw estimate. Paths use independent per-texel random streams so CPU scheduling does not alter the target.

Under this declared static surface model, for a finite-radiance transport solution, the Monte Carlo estimator's expectation is the target integral, subject to floating-point and ray-intersection precision. This does **not** mean a finite-SPP image is exact or that arbitrary Godot effects are represented. Finite samples produce variance. UV texels discretize surfaces, captured panorama cells discretize the sky, and runtime bilinear interpolation adds reconstruction error. Uncovered texels remain zero in the saved raw arrays. Optional `display_gutter_pixels` defaults to one and extends only empty texels in a separate runtime image copy. It reads original covered neighbors only, uses the nearest unique candidate or identical-color ties. Differing-color ties stay empty for unknown or disconnected atlas charts. A receiver proven to have one connected UV chart (shared physical-position and UV edges) may select the first equally nearest sample instead; this closes curved boundary holes without joining unrelated charts. New bakes persist a versioned boolean certificate and a SHA-256 of the exact primitive/position/UV2/index buffers. Reload validates that source signature before using the certificate, avoiding repeated topology work. Missing, malformed, unknown-version or stale certificates use explicit topology certification; they never imply true. The generated runtime texture remains cached. It never propagates from already filled texels, changes covered estimates, or edits variance. This is explicitly biased display reconstruction to reduce atlas-edge seams, not part of the unbiased estimator. Set it to zero for the unmodified raw reference. It does not replace adequate UV margins or atlas resolution. A bright closed loop with unit reflectance may have no finite steady-state solution. Per-texel luminance sample variance is saved; with one sample it is undefined and stored as `-1`.

## Supported inputs and explicit limitations

- Visible static, unskinned, undeformed triangle `MeshInstance3D` geometry. `ArrayMesh` and built-in `PrimitiveMesh` are supported. Smooth sphere normals and nonuniform/mirrored transforms are represented; degenerate zero-area world triangles are omitted and counted. Missing receiver UV2, overlapping UV interiors, non-triangle surfaces, hidden/non-static geometry and active deformations fail with source diagnostics.
- Constant opaque `StandardMaterial3D` with Lambert or Burley diffuse and disabled or Schlick-GGX specular, including roughness and metallic. Source colors are converted from sRGB to linear once. Physical emission uses `emission_energy_multiplier * emission_intensity`; nonphysical emission uses its multiplier. Backface-culling and two-sided surfaces follow explicit material flags.
- Textures, custom shader materials, transparency, vertex-color albedo, zero-roughness specular delta lobes, toon/wrapped diffuse, clearcoat, anisotropy, refraction, SSS, rim, AO/bent-normal overrides and other unrepresented lobes fail validation. They are not replaced with simpler materials silently. Default Burley/GGX materials and the white-box scene's smooth sphere are accepted.
- `DirectionalLight3D` supports delta sources and finite angular diameters in `[0,180)` degrees. Finite disks are sampled uniformly in solid angle with a matching PDF, full geometry visibility, and perpendicular-plane illuminance normalization; they are not collapsed to the center ray. This permits the white-box scene's 0.5-degree sun and traces its penumbra. `BAKE_STATIC` contributes direct and indirect lighting; `BAKE_DYNAMIC` contributes indirect only, retaining realtime direct light. `light_indirect_energy` scales secondary transport separately. Physical light units use lux and correlated color; the nonphysical source is converted to the integrator's radiometric convention. Negative lights and light linking are rejected. Constant rectangular `AreaLight3D` sources use uniform-area next-event estimation and full geometry visibility; static/dynamic direct-light semantics match directional sources. Radiance, normalization, closest-point range falloff and physical-unit attenuation follow the declared FRP rectangle source model. An authored analytic area light and an emissive mesh panel remain two separate sources; neither is silently removed or replaced. Textured area lights, omni and spot lights remain unsupported; emissive triangle panels are also supported. `BAKE_DISABLED`, editor-only, hidden and sky-only direct lights are recorded as excluded with their reasons.
- `CAPTURE_SCENE_SKY` reads `RenderingServer.environment_bake_panorama(..., false, ...)`, preserving the engine's environment energy/ambient blend and sky rotation. It captures radiance, not filtered irradiance or a tonemapped screenshot, and applies no camera exposure. Canonical FengSky sources are identified through that component's exact shader identity check and actual bound lights. In the private capture only the independent disk-color terms for represented analytic sources are zeroed; scattering irradiance stays unchanged. Sky-only and otherwise unrepresented disks remain. Unknown custom shaders are captured as authored and explicitly reported as having unverified solar-disk decomposition. It uses the selected `WorldEnvironment` sky boundary, not `FengSkyLight`'s local-geometry capture; using that local capture as infinity would count the same geometry again. The captured sky still includes its shader's own radiance limits and finite-resolution reconstruction. Analytic sunlight uses authored illuminance; its spatial atmospheric attenuation and cloud shadows are not modeled by the surface backend. External volumetric-cloud compositing passes and local participating-media scattering are outside this surface/sky model and are disclosed in the bake report. Thus an unbiased raw estimate of this declared input model is not a claim of exact agreement with the complete FRP scene. Multiple distinct camera/world environments are rejected rather than choosing one implicitly. Headless/dummy rendering cannot capture a shader sky; a missing capture fails without substituting black.

## Runtime storage and API

Backend contract **v4** adds finite-angle directional disk transport to the v3 scene API (`bake_scene_atlases(scene, options)`, smooth normals, constant PBR transport, directional and rectangular area sources, a captured radiance panorama, CPU workers, cancellation and progress). The volume checks the loaded contract before tracing. Rebuild the addon DLL and restart the editor when upgrading a previously loaded library. The v2 `bake_atlases(...)` entry point remains available for existing analytic callers and tests; `mesh_id=-1` still means transport-only geometry.

`bake()` remains a synchronous script entry point after input preparation. For a canonical FengSky with analytic suns, callers must first `await volume.prepare_environment_capture()` and verify its `ok` result; synchronous `bake()` refuses to fall back to the visible disk-containing radiance cache. The Inspector and `bake_current_scene.gd` perform this asynchronous preparation automatically, then use the same input collection/result serialization around a native background thread. A sky change during snapshot generation rejects that snapshot. Native `request_cancel()` is sticky for that integrator instance; each volume bake creates a fresh instance. `get_progress()` is thread-safe.

`FengLightmapData` saves linear RGBAF CPU layers, luminance variance, material/environment-model description, contract version, physical-light setting, bounds, receiver paths, source counts, display-gutter metadata and path statistics. Binary `.res` outputs use Godot lossless resource compression; `.tres` remains available. There is no SH or lossy compression step. Runtime `Texture2DArray` creation is cached per resource; each volume also reuses its `LightmapGIData` while toggling `enabled`. This avoids repeated atlas conversion/upload on ordinary enable/disable refreshes. The typed `baked_data` property accepts `FengLightmapData` subclasses; external resource loading checks that same type contract. Replacing it invalidates the volume cache. Call `invalidate_runtime_cache()` after intentionally mutating a resource's raw atlas arrays in place.

Texture-only runtime data stores receiver bounds in `LightmapGIData` for instance culling and leaves dynamic SH probe arrays empty. Legacy resources derive missing bounds from their receiver meshes when binding. Use the matching rebuilt editor for this bounds behavior; valid saved atlases remain reusable.

Build the native CPU extension from the addon's `native/` directory with the repository's existing godot-cpp checkout:

```powershell
scons platform=windows target=template_debug arch=x86_64
```

The addon DLL is written under `feng-lightmap-mc/bin/`; run it with the matching Feng Godot editor.

## Validation

From a project that stages this addon under `res://addons/feng-lightmap-mc/`:

```powershell
godot --headless --path . --script res://addons/feng-lightmap-mc/tests/test_frontend_v3.gd
godot --headless --path . --script res://addons/feng-lightmap-mc/tests/test_estimator.gd
godot --headless --path . --script res://addons/feng-lightmap-mc/tests/test_async_v3.gd
godot --headless --path . --script res://addons/feng-lightmap-mc/tests/bake_analytic_fixture.gd
godot --headless --path . --script res://addons/feng-lightmap-mc/native/tests/test_transport_v3.gd
godot --path . --rendering-method frp --rendering-driver d3d12 --script res://addons/feng-lightmap-mc/tests/test_private_sky_capture.gd
godot --path . --rendering-method forward_plus --rendering-driver d3d12 --script res://addons/feng-lightmap-mc/tests/test_texture_only_visibility.gd
```

To rebake the actual white-box scene with its current sky and finite-angle sun, use a GPU renderer (not headless/dummy) and the same asynchronous backend as the Inspector. The helper waits for the sky, saves a separate candidate by default, and never changes the authored scene or pipeline:

```powershell
godot --path . --rendering-method frp --rendering-driver d3d12 --script res://addons/feng-lightmap-mc/tests/bake_current_scene.gd -- --resolution=128 --samples=512 --workers=8 --output=res://Temp/lightmap_current_candidate.res --report=res://Temp/lightmap_current_candidate.json
```

The frontend suite checks default UI actions, transformed smooth normals, mirrored winding, material units and fields, directional/rectangle bake semantics, raw-preserving display gutters, transport-only geometry, explicit environment overrides and unsupported-model diagnostics. The legacy native tests retain their independent uniform-plane and infinite diffuse-cavity references, including UV-overlap rejection. The save/reload fixture traces an emissive panel outside receiver bounds with no UV2, saves to a collision-checked `user://` test path, reloads the resource and verifies runtime `LightmapGIData` construction. The white-box scene has a separate integration test. The async suite verifies that a heavy requested bake advances editor frames, cancels, and writes no partial output. Additional v3 native tests exercise the new contract and transport distributions.

The texture-only GPU fixture renders an identical constant atlas from two camera positions and checks that a dynamic object retains its independent ambient lighting. It has six numerical checks. Its `-- --legacy-empty-bounds-control` restores the old renderer bounds and is expected to fail the two atlas-color checks. The white-box project is additionally tested through its actual FRP compositor at frontal and grazing angles.
